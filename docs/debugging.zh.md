# 没有 UART 怎么找原因

[Русский](debugging.md) · [English](debugging.en.md)

这个方法不只在这里有用。

- 镜像从原厂固件写入非活动槽位，这样原厂固件的启动还在，出问题可以退回去。
- 在镜像里加一个服务，每秒把 dmesg 和进程列表存到闪存上，每次启动单独一个文件夹。这一点很重要。我最开始的结论之所以错，就是因为断电重启时新一次启动覆盖了上一次的数据，我把断电的时刻当成了卡死。
- 在原厂固件里挂接这个槽位的 rootfs_data 卷（ubiattach，然后从 /dev/ubiN_M 里 cat 出来），再在电脑上用 ubireader 解开文件，因为原厂内核挂载不了 zstd 压缩的 UBIFS。
- 等系统能连上网络以后，通过 SSH 实时读取 /dev/kmsg，就能当场看到内核崩溃。驱动模块的测试不用刷机。用 SSH 把 ko 传过去，再用 insmod 加载。

从 1.2.4 开始，公开发布的镜像里已经内置了这些功能。启动日志写到 crash_syslog 分区（mtd27）。内容是启动开始时的 dmesg，之后四分钟内每 15 秒一次，最后一次还会带上接口地址、网络配置和系统日志的末尾。内核崩溃通过 mtdoops 写到 crash 分区（mtd26）。在原厂固件里这样读取。

```
dd if=/dev/mtd27 bs=64k 2>/dev/null | strings
dd if=/dev/mtd26 bs=64k 2>/dev/null | strings
```

## 我自己犯过的错

我有两次写过 Wi-Fi 7 不能用，两次都错了。第一次我把自己实验带来的副作用当成了驱动的限制，后来又以为是内核层面 MLO 的问题。真正的原因很普通。接入点接口有自己的 disabled 设置，和射频本身的设置是分开的，有几次运行时我没注意，这个 disabled 一直是打开的。
